# 分辨率 / 宽高比支持矩阵与规则分析

用户可选：**宽高比** 16:9 / 1:1 / 9:16，**分辨率** 480p / 720p / 1080p。本文档整理各**图片模型**与**视频模型**的支持情况，并给出前端展示、UserInput 描述、图-视频适配与 fallback 的规则建议（仅分析，不直接改代码）。

---

## 一、支持度总表

### 1.1 图片模型（关键帧）

| 模型 | 16:9 | 1:1 | 9:16 | 480p | 720p | 1080p | 说明 |
|------|------|-----|------|------|------|-------|------|
| **Nano Banana (2.5 Flash)** | ✅ | ✅ | ✅ | ✅ | ✅ | ⚠️ 不达标 | API 无 imageSize，固定输出；1080p 时最大 1344×768（横）/768×1344（竖）/1024×1024（方），下采样保持原尺寸，无法达到 1920×1080。 |
| **Nano Banana 2 (3.1 Flash)** | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | 支持 512px/1K/2K/4K，可覆盖 480p/720p/1080p 全档。 |
| **Nano Banana Pro (3 Pro)** | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | 支持 1K/2K/4K，可覆盖全档。 |
| **Seedream v4.5** | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | API 最小 3,686,400 像素；按比例请求后下采样到 TARGET_PIXELS，全档支持。 |
| **GPT Image 2 (WaveSpeed)** | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | API `resolution` 在实测栅格上按 TARGET 取**最小** 1k/2k（480p 与 720p→**1k**，1080p→**2k**，不请求 4k）+ `aspect_ratio` + `quality=medium`，再下采样到 TARGET_PIXELS；与 NB 选最小 `image_size` 思路一致。 |

## 二、规则与设计建议

### 2.1 前端展示：是否后端控制、如何更通用

- **现状**：前端若写死「16:9/1:1/9:16」「480p/720p/1080p」，加新工具或新档位时要改前端。
- **建议**：**由后端按「当前选中的 image_tool / video_tool」返回该工具支持的 (aspect_ratio, resolution) 可选列表**，前端只做展示与回传。
  - 接口形态示例：`GET /api/options/capabilities?image_tool=nano_banana_2&video_tool=pollo_seedance` → 返回 `{ "aspect_ratios": ["16:9","1:1","9:16"], "resolutions": ["480p","720p","1080p"], "warnings": [] }`。
  - 若某组合不被当前视频工具支持（如 Sora 2 无 1:1），可返回 `warnings` 或在该工具下隐藏 1:1，或保留选项但提交时后端做映射（当前即 480p→720p 等）。
  - **通用性**：新增 image/video tool 时，只需在后端维护一张「工具 → 支持的 aspect_ratio / resolution」表（或从现有 tool 的 convert_* 逻辑里推导），前端无需改选项结构，只根据接口收缩/置灰选项即可。

---

### 2.2 UserInput 替换 UserOption 时如何描述

- **现状**：UserOption 里有 `aspect_ratio`、`resolution`、`image_generation_tool`、`video_generation_tool` 等，用于 pipeline 与 regenerate。
- **若用 UserInput 替代/补全 UserOption**，建议在 schema 中：
  - **保留枚举值不变**：`aspect_ratio: "16:9" | "1:1" | "9:16"`，`resolution: "480p" | "720p" | "1080p"`，便于与现有 TARGET_PIXELS、convert_* 一致。
  - **描述文案**：在 field description 中写明「部分模型不支持全部组合：如 Kling 仅输出固定尺寸，Sora 2 仅 720p，Seedance v1.5/Wan 2.6 无 480p；选择后若当前工具不支持，将自动映射或使用 fallback」。
  - **可选**：在 UserInput 中增加 `allow_auto_downgrade: bool` 之类，表示「当所选工具不支持当前 resolution 时是否接受自动降档（如 480p→720p）」，便于后续做明确提示或计费区分。

---

### 2.3 图片与视频如何适配；fallback 是否相通

- **适配关系**：
  - 关键帧由**图片模型**按用户选的 `(resolution, aspect_ratio)` 生成并下采样到 `TARGET_PIXELS[(resolution, aspect_ratio)]`。
  - **视频模型**收到的仍是同一套 `(resolution, aspect_ratio)` + 同一张关键帧 URL；各视频工具内部按自身能力做映射（如 480p→720p、或固定 1280×720）。
  - 因此**图与视频的“适配”**是：**统一用用户选项生成关键帧，视频侧按工具能力接受同一张图并输出可能不同的成片尺寸**；若成片与关键帧尺寸不一致，由后续 **assemble 阶段**做归一化（scale/pad 等）。

- **Fallback 是否相通**：
  - **图片 fallback**：同一 (resolution, aspect_ratio)，换图片模型重试；输出仍会下采样到同一 TARGET_PIXELS，**分辨率/宽高比一致**，可继续给任意视频工具用。
  - **视频 fallback**：主模型失败后切到 fallback 模型（如 Seedance v1 → Wan 2.6），**仍传同一 (resolution, aspect_ratio) 与同一关键帧**；fallback 模型可能把 480p 映射成 720p（Wan 2.6）或固定 1280×720（Kling），即**成片分辨率可能变化，但关键帧不变**。
  - **不相通之处**：
    - 若用户选 **Kling**，成片永远是 1280×720/720×1280/960×960，与用户选的 480p/1080p **无关**；fallback 到 Seedance/Wan 后，成片又会按用户选的 resolution 输出，**同一次任务内前后片段可能分辨率不一致**，需靠 assemble 归一化。
    - 若用户选 **480p** 且主模型为 **Wan 2.6**，会先被映射成 720p；fallback 到 Seedance v1 时仍传 480p，成片为 480p，**同一任务内 720p 与 480p 混用**，同样需 assemble 处理。
  - 结论：**fallback 在“用同一关键帧、同一用户选项”意义下是相通的**；但**成片分辨率可能因工具能力不同而不一致**，需在规则上约定「以 assemble 归一化为准」，并在前端或说明中提示「部分模型会自动调整输出分辨率」。

## 三、汇总表（便于定规则）

| 维度 | 图片侧 | 视频侧 |
|------|--------|--------|
| **全支持 (16:9/1:1/9:16 × 480p/720p/1080p)** | NB 2、NB Pro、Seedream、GPT Image 2 | Seedance v1、Wan 2.5 |
| **不支持 1080p（或非标准）** | NB 2.5 Flash（1080p 仅能到 1344×768 等） | Sora 2（仅 720p）、Sora 2 Pro（1080p 为 1792×1024） |
| **不支持 480p** | 无 | Seedance v1.5、Wan 2.6（→720p）、Sora 2/Pro（→720p） |
| **不接 resolution/AR（固定输出）** | 无 | Kling v3（1280×720 / 720×1280 / 960×960） |
| **1:1 特殊** | 全支持 | Sora 2/Pro 无 1:1，回退到横屏尺寸 |

建议定规则时：
1. **前端**：分辨率/宽高比选项由后端按当前 image_tool、video_tool 返回可选项或提示。
2. **UserInput/UserOption**：继续用统一枚举；描述中注明「部分组合会被自动映射或固定输出」。
3. **图-视频与 fallback**：关键帧统一按用户选项生成；视频工具按能力映射；成片尺寸不一致时统一由 assemble 归一化，并在产品层面接受「Kling 固定尺寸」「Sora 仅 720p」等说明。

## 四、视频成片对齐到严格 480p/720p/1080p（与图片一致）

若要求**视频出来后也像图片一样，严格落到 480p/720p/1080p 标准尺寸**（即 TARGET_PIXELS），可对成片做与图片相同的处理：与目标尺寸差异在 **3% 以内**（沿用 `DOWNSCALE_FORCE_EXACT_THRESHOLD = 0.03`）时，强制 resize 到标准宽高；否则只做**等比例缩小**（成片 ≥ 目标时缩到不超过目标框），不放大、不裁切、不 pad 填满。

**「在视频管线里做 scale」**：指的就是上述这一种操作——对成片做**等比例缩小**（必要时 3% 内强制到标准），不做放大、不加黑边填满。实现上即「视频版的 downsample_to_target」：读成片分辨率，算 scale = min(目标宽/成片宽, 目标高/成片高, 1.0)，若 scale<1 则缩放到 (成片宽×scale, 成片高×scale)，若该结果与目标在 3% 内则改为直接输出目标尺寸；无需 pad。

### 4.1 两种策略

- **策略 A（只等比例缩小）**：成片 **≥ 目标** 时才对齐；成片任一边 **< 目标** 则不对齐，保持成片尺寸。此时 Wan 2.5 的 480p 两档、Seedance 的 720p 两档为「不支持严格标准」。
- **策略 B（与图片一致：3% 内可放大到标准）**：与目标差异 **< 3%** 时（无论成片略大还是略小），都强制 resize 到标准尺寸。这样**成片略小**的也可以对齐：
  - **Wan 2.5** 16:9 480p：842×474 → 854×480，约 1.4% 放大，&lt; 3% → 可对齐。
  - **Wan 2.5** 9:16 480p：474×842 → 480×854，约 1.3% 放大 → 可对齐。
  - **Seedance v1** 16:9 720p：1248×704 → 1280×720，约 2.6% / 2.3% 放大 → 可对齐。
  - **Seedance v1** 9:16 720p：704×1248 → 720×1280，同上 → 可对齐。
  - **Seedance v1.5** 16:9/9:16 720p：1268×728、728×1268，与 1280×720/720×1280 差约 1%～2% → 可对齐。

采用**策略 B** 时，Wan 2.5、Seedance v1、Seedance v1.5 在「成片略小」的档位也都可以在 3% 内对齐到标准，**没问题**。

### 4.2 按报告实测逐档位判定（策略 B：3% 内可放大到标准）

| 请求档位 | Seedance v1 | Seedance v1.5 | Wan 2.5 | Wan 2.6 | Kling v3 | Sora 2 | Sora 2 Pro |
|----------|-------------|---------------|---------|---------|----------|--------|------------|
| **16:9 480p** (854×480) | ✅ | ✅ | ✅ 略小&lt;3% | ✅ | ✅ | ✅ | ✅ |
| **16:9 720p** (1280×720) | ✅ 略小&lt;3% | ✅ 略小&lt;3% | ✅ | ✅ | ✅ | ✅ | ✅ |
| **16:9 1080p** (1920×1080) | ✅ | ✅ | ✅ | ✅ | ❌ 需放大&gt;3% | ❌ 需放大 | ❌ 不足 |
| **1:1 480p** (480×480) | ✅ | ✅ | ✅ | ✅ | ✅ | ❌ 无 1:1 | ❌ 无 1:1 |
| **1:1 720p** (720×720) | ✅ | ✅ | ✅ | ✅ | ✅ | ❌ 无 1:1 | ❌ 无 1:1 |
| **1:1 1080p** (1080×1080) | ✅ | ✅ | ✅ | ✅ | ❌ 需放大 | ❌ 无 1:1 | ❌ 无 1:1 |
| **9:16 480p** (480×854) | ✅ | ✅ | ✅ 略小&lt;3% | ✅ | ✅ | ✅ | ✅ |

### 4.3 最终「不支持」汇总（策略 B 下）

在**允许 3% 内放大到标准**的前提下，真正无法在 3% 内对齐的只有：

- **Kling v3**：**不支持 1080p**（横/竖固定 1280×720/720×1280，方 960×960；要出 1080p 需放大 &gt;3%）。480p/720p 可等比缩小到标准，支持。
- **Sora 2**：**不支持 1080p，且不支持 1:1**（仅 1280×720/720×1280，无 1:1 输出；1080p 需放大，1:1 回退到横屏无法对齐方框）。
- **Sora 2 Pro**：**不支持严格 1080p，且不支持 1:1**（1080p 成片 1792×1024/1024×1792，宽或高不足 1920/1080；1:1 回退到横屏）。

**Wan 2.5、Seedance v1、Seedance v1.5** 在成片略小的档位（Wan 2.5 的 480p 两档，Seedance 的 720p 两档）均在 3% 内可对齐，**可以算支持**。

### 4.3.1 Seedance v1.5 / Wan 2.6 选 480p 时（API 仅 720p/1080p）

用户选 480p 时，API 请求 720p，成片再**等比缩小到 480p**（TARGET_PIXELS）。根据实测报告：

- **Wan 2.6** 请求 720p 时输出 **1280×720**（16:9）/ **720×1280**（9:16）/ **960×960**（1:1），等比缩到 854×480 / 480×854 / 480×480 与目标差 &lt;1%，**≤3%**。
- **Seedance v1.5** 请求 720p 时输出 **1268×728**（16:9）或 **728×1268**（9:16）等，与 1280×720 差约 1%～2%，等比缩到 480p 后与 854×480 差约 2% 内，**≤3%**。

结论：**等比缩小 720p 成片到 480p 是正常且落在 3% 内的**，逻辑与计费、regenerate 一致（见下）。

### 4.4 小结

- **实现**：视频管线里只做「等比例缩小 + 3% 内强制到目标」，即视频版的 downsample_to_target，不做放大、不 pad。
- **成片略小**：若采用与图片一致的 3% 阈值（策略 B），略小也在 3% 内时允许 resize 到标准，则 **Wan 2.5、Seedance 全档位均可对齐，没问题**。
- **真正不支持**：**Kling 不支持 1080p**；**Sora 2 不支持 1080p 和 1:1**；**Sora 2 Pro 不支持严格 1080p 和 1:1**。
