ALB (Application Load Balancer) — 全自动路由说明
ALB = AWS Application Load Balancer — 全自动路由，无需人工干预
K8s 中 VideoAgent 和 Media-Service 的 Ingress 都用 AWS ALB。

DNS → ALB 自动：Route 53 Private Hosted Zone（cuti.internal）自动把 media-dev.cuti.internal 指向 ALB 内网地址。 AWS Load Balancer Controller 创建 Ingress 时自动注册 DNS，无需手动配置。
ALB → Pod 自动：AWS VPC CNI 插件给每个 Pod 分配 VPC 内网 IP，Load Balancer Controller 自动把 Pod IP 注册为 Target Group 后端。 HPA 扩缩容时新 Pod 自动注册，Pod 终止后自动摘除。
Pod IP 变化无影响：target-type=ip 模式下，所有 Pod IP 的注册/注销全自动。Nginx 只知道 media-dev.cuti.internal 这个 DNS 名，解析由 AWS 自动完成。

Scheme: internal — 只在 VPC 内部可达，外部用户无法直接访问 K8s 服务，必须经 EC2 Nginx 转发。
Target-type: ip — ALB 直接路由到 Pod IP（不经 NodePort），延迟更低。
Idle timeout: 1200s — 支持长连接（VideoAgent 生成视频可能需要数分钟）。
负载均衡策略：Round-Robin / Least Outstanding Requests 分配到各 Pod，健康检查失败自动摘除。

Media-Service — CPU 密集型（FFmpeg 容量分析）

核心模型：只需要三个数字

1 次 ensure_on_s3 = 5 CPU-seconds
FFmpeg 编码 1080p 3s 视频 (libx264 ultrafast + scale/pad + strip_audio + watermark) = 1 个 CPU 跑 5 秒。

60s 任务 = 25 次 ensure_on_s3 = 125 CPU-seconds
20 shots × 1.25 (built-in retry) = 25 次。其他操作 (segment, concat) 全是 -c copy，CPU 可忽略。

这 25 次操作分散在 ~5 分钟 (300s) 的 video gen 阶段
semaphore=10, API 响应 60-180s → ops 在 5 min 内陆续到达，不是同时发生。
每任务平均 CPU 需求 = 125 / 300 = 0.42C

Credit Estimation — 积分预估公式 & 代码流程

积分预估接口 & 暂停逻辑

提交前 (新接口)                              暂停时 (interrupt payload)
   │                                              │
   │  POST /estimate-credits                      │  get_credit_estimate_for_gate(state, step)
   │  { user_option, is_audio_driven,             │    暂停1 (after_character): remaining = kf + video
   │    audio_duration_sec?,                      │    暂停2 (after_keyframe):  remaining = video only
   │    audio_segment_durations? }                │    暂停3 (after_shots):     remaining = 0
   ▼                                              ▼
estimate_video_agent_credits(user_option, ...)  →  CreditEstimateResult (Pydantic)

══════════════ 核心公式 (cost_estimation.py) ══════════════

Step 1: Scene/Shot 估算 (1:1)
  threshold = get_split_threshold(user_option)
    ├─ audio-driven 普通模式:   min(video_durations) ≈ 3s
    ├─ audio-driven LIP_SYNC_MV: max(lipsync_durations) ≈ 10-15s
    └─ video-driven:            min(video_durations) ≈ 3s
  shots = ceil(total_duration / threshold)

Step 1.5: 推算每 shot 视频时长
  est_shot_duration = max(3, threshold) ≈ 3s  ← 关键改进! 不再固定 5s
  cost functions 传入此真实时长

Step 2: Keyframe 数量
  base_keyframes = shots × (enable_continuity_mode ? 2 : 1)
  reflection_mult = enable_keyframe_reflection ? 1.25 : 1.0
                    enable_show_reflection ?     max(mult, 2.0)
  keyframe_count = round(base_keyframes × reflection_mult)

Step 3: 查单价 → ToolService.calculate_cost(duration=est_shot_duration)
  keyframe: Nano Banana 2 = $0.067/image
  video @3s: Seedance v1 Pro 1080p = $0.144/shot
  lipsync @3s: Wan 2.6+audio 1080p = $0.225/shot

Step 4: 积分计算 (含 built-in retry)
  keyframe_usd = keyframe_count × kf_cost × 1.2  (built-in character consistency)
  video_usd    = shots × avg_video_cost × 1.25  (built-in video consistency)
  total_credits = round((keyframe_usd + video_usd) × 100)

══════════════ 例子 1: Video-Driven 60s (默认参数) ══════════════
  threshold=3s → shots = 20, est_shot_duration = 3s
  keyframes = 20 × 1 = 20 | kf_cost = 20 × $0.067 × 1.2 = $1.61
  video = 20 × (0.5×$0.144 + 0.5×$0.225) × 1.25 = 20 × $0.1845 × 1.25 = $4.61
  total = $1.61 + $4.61 = $6.22 = 622 credits

══════════════ 例子 2: Audio-Driven 45s, lipsync=100% ══════════════
  3 segments [12s, 18s, 15s], threshold=3s → shots = 4+6+5 = 15
  kf_cost = 15 × $0.067 × 1.2 = $1.21
  video = 15 × $0.225 × 1.25 = $4.22  (≈ 45s × $0.075 × 1.25)
  total = $5.43 = 543 credits

══════════════ 例子 3: 首尾帧 + VLM反思 30s ══════════════
  Seedance Lite (有尾帧), lipsync=0%, threshold=3s → shots = 10
  keyframes = 10 × 2(首尾帧) × 1.25(VLM反思) = 25
  kf_cost = 25 × $0.067 × 1.2 = $2.01
  video = 10 × $0.27(Lite 3s) × 1.25 = $3.375
  total = $5.39 = 539 credits

══════════════ 反思/Retry 说明 ══════════════
  [Always-ON] Built-in Consistency Check
  • keyframe: check_character_consistency_llm → ×1.2 (image_tool_wrapper.py:406)
  • video: check_video_consistency_llm → ×1.25 (video_tool_wrapper.py:348)
  代码已自动乘入 → BUILTIN_KEYFRAME_CONSISTENCY_MULT / BUILTIN_VIDEO_CONSISTENCY_MULT

  [可选] VLM Keyframe Reflection Node (前端 enableKeyframeReflection, 默认关闭)
  • ~25% 概率触发重生 → 额外 ×1.25 (叠加在 built-in 之上)
