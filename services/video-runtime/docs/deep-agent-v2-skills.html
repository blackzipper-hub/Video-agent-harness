1. 代码调用结构

用户消息从前端进入 V2 API，经 Harness 持久化与调度，由 Coordinator（LangGraph）选 Skill / 提计划，再由 CapabilityExecutor 分发到沙箱、进程内服务或 VideoAgent。

层关键模块职责
前端features/deep-agent-v2/run / message / SSE / artifacts
APIapi/v2/v2_endpoints.py/chat-v1/service/v2/*
Harnessharness.py计划校验、任务调度、artifact
Coordinatorcoordinator.py + deep_agent_runtime.pyLLM 工具循环
Toolstools.pylist/load skill、propose_plan_patch、run_skill_script
Executorexecutors.pysandbox / local.service / delegate / mcp

一次消息主路径

  1. POST /v2/runs/{id}/messages → DynamicHarness.add_message
  2. DeepAgentCoordinator.run → Runtime 工具：load_skill / propose_plan_patch …
  3. commit_agent_patch → 落库 tasks → CapabilityExecutor.submit
  4. 产出 artifact → 再协调；delegate 可能经 /internal/video-agent/events 异步完成

2. Skill 加载逻辑

根目录与信任

  • skills/.system → trusted，可走 local.service / delegate
  • skills/external → untrusted，可执行合同仅允许 sandbox.run
  • .cuti-disabled → 目录级禁用

两类 Skill

  • Instruction-only：无 cuti-contract，不注册 capability
  • Executable：有 cuti-contract → CapabilityRegistry

资源列表跳过 .cuti-* 与以 . 开头的路径段（如 .filtered）。

示例类型执行
open-montageinstruction-only组合阶段能力 + 可选 scripts
open-montage-tools.system local.serviceopen_montage.tool.invoke
seedance2instruction + scriptrun_skill_script + Ark 桥
media-concat.systemHostGateway media.concat

3. 热加载逻辑

入口：POST /chat-v1/service/v2/internal/skills/reload → reload_v2_skills()。

  1. catalog.reload() 重新扫盘
  2. build_registry / replace_all 刷新 capability
  3. _apply_runtime_policy（沙箱关闭则禁用 sandbox.run）
  4. runtime.reload_skill_files() 刷新虚拟 /skills/**

Reload 立即生效

  • SKILL.md / 资源 / scripts 内容
  • Capability 注册表
  • .cuti-disabled / install / delete
  • list_skills / list_capabilities 视图

需改代码并重启

  • 新 local.service target 分支
  • 新 HostGateway capability
  • 系统 prompt / LangGraph 结构
  • 新 VideoAgent 阶段服务接线

热加载刷新的是「Skill 包 + 注册表」，不是「Agent Python 业务逻辑」。

4. 沙箱是什么？逻辑如何？

沙箱 = 独立 sandbox-worker 在隔离容器（默认 python:3.11-slim）中执行 Skill 代码，写出 output/result.json，由 Agent 收成 artifact。开关：DEEP_AGENT_V2_SANDBOX_ENABLED。

两条入口

路径触发说明
propose_plan_patch + sandbox.run 有 cuti-contract 按 sandbox 策略跑 entrypoint
run_skill_script 协调器工具 仅 scripts/*；instruction-only 也可用

Host Gateway

容器通过注入的 host_dispatch 回调 Agent：

POST /v2/internal/host/dispatch → HostGateway

  • 媒体：media.concat / extract_frame / trim / speed_adjust
  • 生成：provider.generate
  • 其它：http.request、artifact.*、log、progress

local.service（outline/character 等）在 Agent 进程内执行，不进沙箱；external Skill 不能声明 local.service。

5. 可直接热加载 vs 需代码适配

可直接热加载

  • Instruction-only：只组合已有 capability
  • scripts 仅依赖已有 host / Ark 桥
  • external + sandbox.run 完整合同
  • 启停已存在 Skill（.cuti-disabled）

需要代码适配

  • 新 DB/阶段服务 → executors 新 target
  • 新宿主能力 → host_gateway +（可选）Media
  • OM 工具映射扩展 → open_montage_bridge
  • 产品级 local.service → 做成 .system 随发
