# Agent Note: 对话路由的 Create 入口

Status: implemented

[English](2026-09-12-conversation-routed-create-entry.md) | 中文

## 问题

Create 工作区把每条首次消息都交给要求在同一轮次内调用视频规划与构建工具的提示词。即使用户没有要求视频制作，一句问候或普通问题也会启动制作。

## 决策

Create 工作区把首页生成表单提交的请求标记为自动视频请求。显式选择 Workflow 具有相同含义。兼容后端只对这些请求使用强制规划和构建提示词。

其他首次消息获得包含已绑定草稿项目上下文的对话路由提示词。DeepSeek agent（智能体）直接回答问候与普通问题，仅在可见请求要求创建、编辑、检查或导出视频时调用 `video_*` 工具。草稿项目继续作为持久对话容器；如果 agent 选择执行视频工作，它会成为对应的视频项目。

## 考虑过的替代方案

**在后端用关键词分类意图。** 不采用，因为固定词表无法在支持的多种语言中可靠地区分创作请求、视频相关问题和普通对话。agent 已经负责选择工具，并持有必要的请求上下文。

**取消所有入口的自动制作。** 不采用，因为首页生成表单和显式 Workflow 选择承诺一次操作即可开始制作。这些调用方会携带明确的 `automatic_video` 信号。

**推迟到首次视频工具调用时再创建项目。** 不采用，因为导航、transcript（文本记录）持久化、上传与侧边栏状态已经依赖已绑定项目。创建空草稿不会产生构建副作用，并能保留这些约定。

## 后果

发送问候会创建持久对话草稿，但不会创建 Video Build。首页生成和显式 Workflow 请求保留确定性的规划与构建行为。针对性的兼容测试固定两种路由模式，并验证问候在 transcript 中保持可见且不会创建构建。
