# Agent Note: Studio 类型感知检查

Status: implemented

[English](2026-09-09-studio-type-aware-checks.md) | 中文

## 问题

导入的 Studio 代码使用多种 API 数据格式和可选媒体版本。不受支持的 TypeScript 配置项使类型感知 lint 无法可靠报告这些访问问题。盲目删除空值检查会导致空对话或越界的媒体选择触发渲染失败。

## 决策

Studio 启用严格空值与索引访问检查，明确声明聊天事件和媒体记录类型，并在存储和 HTTP 入口保留运行时校验。无法保证元素存在的数组访问继续受到保护。异步回调在等待外部工作后保留取消检查。Fetch 请求头通过 `Headers` 合并；Canvas 编码失败会拒绝导出，而不是返回空图片结果。

## 考虑过的替代方案

**绕过 lint 或屏蔽导入代码。** 不采用，因为这会留下异常数据和异步失败问题，也使协作者无法复现可信的检查结果。

**删除所有看似多余的保护判断。** 不采用，因为索引签名和异步状态变化可能使静态假设强于浏览器实际状态。索引访问检查以及等待后的显式状态读取能够保留必要的保护。

## 后果

前端修复需要明确的事件类型和空状态处理，而不是宽松的数据类型断言。针对性测试覆盖存储记录、请求头表示、结构化输出和 Canvas 失败。生产构建验证打包；提供方可用性与真实媒体质量仍属于独立验收事项。本次修复不改变 DeepSeek agent loop（智能体循环）行为或 Workflow 编译逻辑。
