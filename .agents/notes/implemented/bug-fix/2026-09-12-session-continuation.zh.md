# Agent Note: 对话与视频检查点的会话续接

Status: implemented

[English](2026-09-12-session-continuation.md) | 中文

## 问题

对话的一轮可以结束，但用户消息或 Runtime 规划通知仍可能继续到来。项目修改时间不能为这些轮次排序：普通聊天不必修改视频状态。在轮次结束时关闭浏览器事件流会隐藏后续回复。

## 决策

Studio 在选中 Session 期间保持订阅，并按 Harness 事件序号排序加载的运行状态。回放旧事件不能替换更新的运行投影。上一轮的终态不能取消当前消息 POST；显式停止和请求归属控制取消。

BFF 保留项目绑定的 Harness Session，拒绝不匹配的线程 id，并随后续消息记录持久化项目、Build 和检查点引用。agent（智能体）结合 Session 历史、压缩摘要和当前 Runtime 工具结果进行判断。自动检查点沿用该 Session，并标识真实的前序产物版本。不引入额外的规划循环或对话存储。

这补充了[对话路由](2026-09-12-conversation-routed-create-entry.zh.md)和[动态工作流执行](../architecture/2026-09-09-dynamic-workflow-skills.zh.md)；两者关于意图选择和执行归属的决策继续有效。

## 考虑过的替代方案

**只推进项目时间戳。** 不采用，因为前端关闭事件流后仍无法接收自动续跑，而且项目编辑不是对话修订。

**每个阶段创建新 agent 或检查点存储。** 不采用，因为这会割裂用户历史，并重复已有 Harness 事件日志和 Runtime 持久化执行记录。

## 影响

失败轮次的投影保留模型服务的错误消息和错误码。Studio 同时从历史事件和实时 SSE 恢复最新的失败提示，重新打开 API 额度不足的任务不会隐藏原因。仅显示通用失败标签会丢失可操作的服务诊断；后端映射测试和构建后的浏览器对话快照覆盖额度耗尽及刷新页面的情况。

选中的空闲对话保留一条可重连的 SSE 连接。重启续接需要同时保留两类存储；检查点不会重建已删除的 Session。回归测试覆盖同一绑定上的多条消息、当前产物引用、陈旧快照拒绝、延迟 POST 完成，以及没有浏览器再次发送时到来的自动轮次。付费媒体质量不在这些传输和持久化检查的范围内。
