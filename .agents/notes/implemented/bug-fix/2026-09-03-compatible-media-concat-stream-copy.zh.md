# Agent Note: 参数兼容的媒体片段使用码流复制拼接

Status: implemented

[English](2026-09-03-compatible-media-concat-stream-copy.md) | 中文

## Problem

媒体服务只把 H.264 `yuv420p` 片段视为可以直接复制码流的输入。Seedance 生成的 HEVC Main10 片段参数虽然完全一致，但请求标准化四段视频时仍会启动完整的 H.264 转码，并可能在所有高成本 Provider 步骤已经完成后耗尽媒体客户端超时时间。

## Decision

未设置转场时，拼接操作检查每个输入的视频流和音频流参数。参数完全一致时，即使调用方要求标准化，也使用 FFmpeg concat demuxer 和 `-c copy`，因为标准化表示兼容性保证，不代表必须重新编码。判断包含编码、像素格式、尺寸、帧率、音频存在性、音频编码、采样率、声道数、声道布局和音频时间基。

参数不兼容或存在转场时，继续使用原有标准化转码。若直接拼接后的时长检查发现时间戳异常，则强制进入转码路径，并且不再递归考虑快速路径。

## Verification

媒体服务拼接测试覆盖带 AAC 音频、参数一致的 HEVC Main10 视频，并验证标准化请求会选择 `-c copy`。失败构建中保存的四段 Seedance 视频可拼接为能够解码的 60.28 秒 HEVC 视频，并保留 AAC 音轨。

## Alternatives considered

**始终标准化为 H.264。** 拒绝，因为参数一致的生产片段会付出大量延迟和 CPU 成本，却没有获得额外兼容性。

**保留只允许 H.264 的列表。** 拒绝，因为是否兼容取决于参数是否一致，而不是某一种偏好的编码。

**不检查输入就直接复制。** 拒绝，因为编码、视频或音频参数不一致时可能产生损坏输出或时间戳不连续。

## Consequences

参数兼容的 Seedance 构建可以在数秒内完成无损拼接。混合媒体仍需转码，并且每个直接复制候选都会在拼接前执行元数据检查。
