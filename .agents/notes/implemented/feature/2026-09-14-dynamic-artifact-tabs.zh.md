# Agent Note: 创作工作区的动态产物 Tab

Status: implemented

[English](2026-09-14-dynamic-artifact-tabs.md) | 中文

## 问题

创作工作区把制作状态、最终交付、中间媒体和策划文档渲染在一条长列表中。项目产物增多后难以找到当前结果，而 Workflow 专用面板会使每种新输出都需要额外接入前端。

## 决策

Studio 根据持久化的任务、Build、选择状态和 Artifact 字段派生四个稳定 Tab。制作过程承载执行状态。最终视频优先采用持久化的当前选中视频，其次识别名称明确包含合成、master、导出或最终语义的视频 Artifact，仅在制作完成后才以最新视频兜底。素材承载其余上传和生成内容，并派生全部、图片、视频、音频、文字和其他筛选。文字文档与研究在脚本中作为创作视图保留，同时也可在素材中按类型查找。

Tab 数量和最终视频可用状态在渲染时从当前数据派生。Workflow 不输出 UI Tab 名称，前端也不复制模型的规划状态。

图片、视频、音频和脚本卡片共用一个原生折叠组件，展示持久化的最终生成 Prompt。Prompt 缺失时控件仍保留并说明原因，避免旧产物和上传素材看起来像渲染失败。

## 考虑过的替代方案

**要求每个 Workflow 或模型 Prompt 指定 UI 分类。** 不采用，因为展示元数据会进入模型契约、在不同 Skill 之间漂移，而且旧 Artifact 仍然无法分类。

**保留单一时间顺序结果流。** 不采用，因为项目历史增长后，执行遥测和中间媒体会掩盖当前选中的交付结果。

## 影响

新的 Artifact 类型仍会通过素材的通用兜底显示。未选择交付版本时，带有误导性最终语义的标题可能影响显式识别；持久化选择状态是当前交付的权威依据。构建后的浏览器场景同时覆盖文字筛选，以及图片、片段、音频、剧本和已选最终视频的 Prompt 展开与实时对话事件。
