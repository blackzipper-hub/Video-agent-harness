# Agent Note: 动态 Workflow Skill

Status: implemented

[English](2026-09-09-dynamic-workflow-skills.md) | 中文

## 问题

按名称绑定的编译器注册表阻止独立安装的 Workflow Skill 使用现有持续 PlanPatch 执行器。初始为空的 Resolver 映射还会丢失后续 Catalog 更新。

## 决策

显式声明 agentic 且带有能力白名单的 Skill 使用持续 PlanPatch 执行。共享准入函数服务于 Skill Catalog、Workflow 描述、BFF 选择和计划提交。具名 Cuti Workflow 保留元数据检查。Resolver 即使收到空映射也保留 Catalog 的可变映射。声明生成交付物类型支持纯文档完成，不削弱现有视频完成规则。运行中的 Build 在 Skill 文件未提升声明版本时复用已被计划持久化的准确指令；声明版本发生变化仍视为不兼容，必须显式升级 Project。不属于特定 Workflow 的后期计划排除已锁定的生成 Workflow，但仍保留显式声明的媒体 Skill 和非 Workflow Project 锁。

## 考虑过的替代方案

**让模型生成可执行编译器。** 不采用，因为模型决策应当是经过校验的任务数据，而非具有进程环境权限的代码。

**为每个新 Skill 分配已有生产编译器。** 不采用，因为相似元数据不代表相同的创作或依赖语义。

## 影响

对白字幕复用 Cuti 的转写到模板路径。音频识别不使用剧本提示；提供转写时，模板渲染不使用模型撰写的对白 HTML。显式翻译保留逐片段时间轴，默认字幕使用原声语言。Provider 插件将视频生成暴露为 PlanPatch 操作，使生成与拼接无需另一个 Workflow。模型工具将用户编辑请求视为预览和执行的授权，并将中间构建视为仍需继续的工作，而非最终产物。

字幕语言识别不再跨越原声对白描述。翻译类追问可以进入 Agent；真正的语言冲突返回可理解的 HTTP 422，而非未处理的 500。Studio 提交客户端保留具体错误，通用错误文案不再显示未替换的状态码占位符。

结构化编辑在校验 VideoSpec 前，从持久化修订中提取创作字段，排除执行历史。无 Workflow 的 PlanPatch 仅在冗余 URL 与明确引用的项目产物一致时接受它；转换可以使用之前操作的输出，并为同一来源创建多个版本，同时保留项目版本校验和资源归属检查。这消除了格式和组合障碍，不把外部资源地址视为已授权的项目输入。

新增 agentic Skill 无需修改 Runtime 源码，但需要启用持续规划配置。Runtime 校验和签名执行权限仍然生效。ZIP 安装、重新加载、指令读取、任务执行、越权能力拒绝和文档完成具备集成回归测试。真实模型选择和付费 Provider 质量需要另行实测验收；本次不修改 DeepSeek 核心循环。

实时快照属于调用方，不自动投递：投递 Agent 自己打开的快照会把确认回复再次送入新回合。空确认保留计划和规格版本，同时原子解决检查点。回归测试验证重复确认不会触发投递，而后续任务完成仍产生通知。
